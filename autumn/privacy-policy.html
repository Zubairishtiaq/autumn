Privacy Policy

Last Updated: 14 September 2026

This Privacy Policy explains how ThemeLegend ("we", "us", "our") handles information in connection with the Autumn – Creative Portfolio HTML Template ("the Template"). By using the Template, you agree to this Privacy Policy.

1. Information We Collect

The Autumn template is a static HTML/CSS/JavaScript template. It does not include any server-side code, database, or user authentication system. As such:

  • We do not collect, store, or process any personal data through the template itself.
  • The contact form included in the template is a front-end demonstration only. It does not send or store any data unless you, the buyer, connect it to your own backend service (such as Formspree, EmailJS, PHP mail, etc.).
  • We do not use cookies, trackers, or analytics scripts in the template.

2. Third-Party Services

The template uses the following third-party services, each governed by its own privacy policy:

2.1 Google Fonts

Fonts are loaded from Google Fonts. When a page is loaded, your browser sends a request to Google's servers, which may log your IP address. See Google's Privacy Policy.

2.2 Font Awesome (CDN)

Icons are loaded from the Cloudflare CDN. Cloudflare may log technical data such as IP address. See Cloudflare's Privacy Policy.

2.3 Unsplash

Demo images are loaded from Unsplash. When loaded, Unsplash may collect technical data. See Unsplash's Privacy Policy.

2.4 Google Maps

The contact section embeds a Google Map. Google may collect data when the map is loaded. See Google's Privacy Policy.

2.5 Pexels

Some demo assets may be sourced from Pexels. See Pexels' Privacy Policy.

All images, videos, and patterns shown on the demo site are used for demonstration purposes only. They are copyrighted by their respective authors and are NOT included in the downloadable template package.

Credits for all demo assets are listed in the CREDITS.txt file included with the template. If you intend to use any of these assets in your own project, you must obtain your own license from the original author.

4. Code Protection & Security

The template is written in pure HTML, CSS, and JavaScript. To help prevent common attacks and abuse, the following security measures are already applied:

  • No server-side code — there is nothing to exploit on the server.
  • No database — no SQL injection possible.
  • No user authentication — no session hijacking or credential leaks.
  • No external scripts from unknown sources — only well-known CDNs (Google Fonts, Cloudflare, Unsplash, Google Maps).
  • Content-Security headers via meta tags — including X-Content-Type-Options, X-Frame-Options, and Referrer-Policy.
  • No eval() or inline dynamic code — reducing XSS risk.
  • Rel="noopener" on all external links — preventing tabnabbing.
  • Input length limits on the contact form — preventing buffer overflow attacks.

If you are a developer integrating the template into a server environment, we strongly recommend:

  • Using HTTPS on your server.
  • Sanitizing and validating all form input on the server side.
  • Adding CSRF protection if you implement a backend for the contact form.
  • Serving the site with HTTP security headers (CSP, HSTS, X-Frame-Options, etc.).
